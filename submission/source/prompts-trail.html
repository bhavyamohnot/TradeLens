Artifact 02 · Prompts

The prompt trail, continued

Round 2 rebuilt the app from scratch. Claude wrote the analysis engine itself and briefed two sub-agents in parallel; their briefs are excerpted below.

✓
Prompt 9 · rebuild
Okay, so scratch that, just do this: Create for me everything this project needs from scratch, all the artifacts (submissions), meeting all the requirements with fresh source code. Keep the source code local for now, we will be directly uploading it to vercel.
Claude reframed the product around one outcome: at most three habits, ranked by marginal ₹, each proven with trades and turned into one rule. It then wrote the engine: it reads broker tradebooks, rebuilds round trips, estimates NSE charges, and runs nine habit checks. On the brief's example file it named BANKNIFTY (₹9,100) and cleared the profitable re-entries.
✓
Prompt 10 · data
can you also generate a better/improved example dataset for this project, which meets all the JD and PDF requirements.
A realistic September 2026 Zerodha-style tradebook: 388 buy/sell fills across NIFTY weeklies, BANKNIFTY, RELIANCE futures and equity. It has three planted habits, decoys that must not be flagged, and an answer key computed independently of the app.
✓
Sub-agent brief · interface (excerpt)
…single narrative column (max-width ~760px). It must NOT feel like a dashboard. Order matters: … …never use the word "revenge", never say "you were emotional"… …must work at 375px wide…
Built and type-checked; works at desktop and phone width.
↻
Sub-agent brief · evals (excerpt)
…Planting functions, one per habit key above, each with a `strength` parameter… …recall@3 ≥ 90% and top-1 ≥ 80% for every habit type; clean-control FP rate ≤ 10%… …Do not loosen thresholds or assertions to make things pass.
First run failed the ship bar. Expiry-day losses were hidden under "NIFTY keeps losing" for 25% of traders, and one test expected the wrong number (a 20-trade losing streak; it is 21). False alarms on clean traders sat right at the 10% limit.
Fixed: prefer the narrower habit when it explains most of the cost (75% → 100%), and use a stricter bar for checks that test many variants (false alarms 10% → 0%). The test was corrected, with the reason recorded.
↻
Claude's own follow-up checks (no prompt)
Two checks Claude added itself. It reran the evals on seeds never used for tuning, and it compared each habit's ₹ cost with its own evidence. Both failed: the "charges eating small trades" check dropped to 75–80% on unseen data, and "holding losers" claimed far more ₹ than its averages supported.
Fixed: the planted charges sat exactly on the 5% materiality line, so they were rescaled. Holding losers is now measured only after higher habits claim their trades. Final result on unseen data: 95% recall, 3% false alarms.
↻
Prompt 11
show me the app
The main sample button failed: "We could not load the sample file", and one data note appeared twice.
Fixed: the dev server hadn't picked up the new sample (the production build had it), and the duplicate note was removed.
✓
Prompt 12 · ship (excerpt)
push the updates to github yourself … Once you've done that, confirm if everything is reflected on the hosted vercel url
Shipped. It is live at trade-lens-omega.vercel.app. Both samples were checked on the live site at desktop and phone width. The September sample shows three habits costing ₹57,978, and on the brief's file BANKNIFTY ₹9,100. 91 unit tests and 22 fixed eval cases pass.
